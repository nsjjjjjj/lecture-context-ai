# 대학생 ICT 단편 논문 조사 및 재작성 근거

- 조사일: 2026-08-06
- 대상: ABC 해커톤 2쪽 이상 Word 논문 초안
- 연구 질문: 국내 대학생 ICT 우수 논문은 짧은 지면에서 어떤 순서로 문제, 기술 선택, 구현, 평가, 한계를 설명하며, 이를 강연 용어 AI 프로젝트에 어떻게 적용할 것인가?
- 범위: 국내 ICT 학회의 공식 규정과 원문 수상작, 프로젝트와 직접 관련된 음성인식·자막 학술 논문, 실제 사용한 제품의 공식 문서

## 1. 조사 방법

자료는 다음 세 갈래로 나누어 확인했다.

1. **공식 형식·평가 맥락**: 한국정보처리학회 학부생 논문 분량, 공식 양식, 학부생 경진대회와 수상작 목록
2. **실제 단편 논문 흐름**: 2~4쪽 수상작과 자막 시스템 논문의 초록·서론·설계·평가·결론 전개
3. **관련 기술 근거**: contextual biasing, PhraseSet, 교육용 자막과 확장 자막의 효과·한계

주요 검색어는 `한국정보처리학회 학부생 수상 논문`, `ACK 우수논문 시스템 구현 PDF`, `AI 자막 강의 플랫폼 논문`, `contextual biasing ASR rare words`, `expanded captions college comprehension`이었다. 검색 결과의 요약문만으로 판단하지 않고 학회 원문과 공식 프로그램을 직접 확인했다.

## 3. 근거–판단 매트릭스

| 관찰 또는 주장 | 근거 | 재작성에 반영한 판단 | 신뢰도 |
|---|---|---|---|
| 학부생 ICT 논문은 2쪽 안팎의 짧은 시스템 논문도 가능하다. | ASK 2026 2~3쪽, ACK 2025 1~2쪽 | 분량을 억지로 늘리지 않고 2쪽 완성본으로 구성 | 높음 |
| 우수 단편 논문의 반복 흐름은 문제 → 제안 방법 → 평가 → 한계다. | Bambda, IOC 검증, ACK 2025 금상 논문들 | 기존 `기술 조사 및 구현` 중심 목차를 논문형 5개 절로 변경 | 높음 |
| 기술은 공부 기록이 아니라 설계 선택의 근거로 쓰인다. | 수상작의 서론·설계 장 | PDF.js, PhraseSet, 생성형 AI를 “왜 선택했는가”와 연결 | 높음 |
| 시행착오는 독립적인 개발 일지보다 해당 모듈 안에 넣는 편이 자연스럽다. | 조사한 5편의 설계·구현 흐름 | `시도하면서 수정한 점` 절을 삭제하고 원문 검증, 목록 동기화, 세션 상태 설명에 통합 | 높음 |
| 구조도는 짧은 논문의 구현 설명을 압축한다. | 조사 논문 모두 구조도·흐름도·결과 화면 중 하나 이상 사용 | PDF 분석과 실시간 음성 경로를 하나의 처리 흐름표로 추가 | 높음 |
| contextual biasing은 희귀어 인식 가능성을 높일 수 있으나 부작용도 있다. | Huang 2020, Li 2024, Google 공식 문서 | 전문용어 정확 인식 수와 미발화 용어 오검출을 함께 제시 | 높음 |
| 용어 정의 카드만으로 이해도 향상을 주장할 수 없다. | Stinson & Stevenson 2013 | 제목과 본문에서 `이해도 향상` 대신 `이해 지원·보조` 사용 | 높음 |
| 가상 수치는 실제 결과와 명확히 분리해야 한다. | 한국정보처리학회 연구윤리규정, 사용자 요청 | 초록과 평가 표 앞에 빨간 편집 주석 유지 | 매우 높음 |

## 4. 기존 초안이 어색했던 이유와 수정 방향

| 기존 초안 | 문제 | 수정본 |
|---|---|---|
| `2. 기술 조사 및 구현` | 공식 문서를 읽은 순서가 중심이라 개발 보고서처럼 보임 | `2. 관련 기술 및 설계 방향`에서 문제와 기술 선택을 연결 |
| `2.3 시도하면서 수정한 점` | 시간순 개발 일지로 읽힘 | 초기 문제 → 수정 방식 → 이유를 3.2와 3.3의 해당 모듈에 배치 |
| `집에서 진행한 실험 및 결과` | 표현이 구어적이고 비교 조건이 뒤늦게 나옴 | `4. 프로토타입 평가`에서 환경, 동일 음원, 분모, 지표를 먼저 제시 |
| PhraseSet 적용 결과만 강조 | 문맥 편향의 오검출 가능성을 숨길 수 있음 | 미발화 용어 오검출을 같은 표에 포함 |
| `적응형`이라는 제목 | 실제로는 정적 PhraseSet을 주입하는 데모라 과장될 수 있음 | `강연 PDF 기반 전문용어 사전`으로 구현 범위를 직접 표현 |
| 설명 카드가 이해도를 높인다는 인상 | 사용자 평가가 없어 근거 부족 | 이해를 “보조하도록 설계”했다고 한정하고 후속 사용자 평가 제시 |

## 5. 최종 채택한 논문 흐름

1. **서론**: 강연 전문용어의 자막 오류와 의미 이해 문제 → 선행연구의 시사점 → 프로젝트 목적과 기여
2. **관련 기술 및 설계 방향**: contextual biasing과 PhraseSet의 역할·한계 → PDF.js·구조화 출력·WebSocket의 선택 이유
3. **제안 시스템의 설계 및 구현**: 전체 처리 흐름 → PDF 기반 용어 사전 → 실시간 자막과 이해 보조 → 핵심 시행착오와 보완
4. **프로토타입 평가**: 가정 환경, 동일 녹음, 10개 용어 30회, 전문용어 정확 인식과 오검출 → 결과와 제한
5. **결론 및 향후 연구**: 구현한 내용과 배운 판단 → 현재 한계 → 실제 측정과 사용자 평가 계획

이 흐름은 국내 학부생 수상 단편 논문의 공통 구조를 따르면서도, 이 프로젝트가 대규모 연구가 아닌 발표 가능한 웹 MVP와 소규모 예비 실험이라는 사실을 유지한다.

## 6. 채택하지 않은 주장과 남은 확인 사항

### 채택하지 않은 주장

- PhraseSet이 전문용어를 **교정하거나 정확도를 보장한다**.
- 용어 설명 카드가 청중의 **이해도를 향상한다**.
- 원본 PDF와 음성을 저장하지 않으므로 **외부 전송도 없다**.
- 해외 연구의 개선율을 이 프로젝트의 한국어 데모 결과처럼 사용한다.
- 수상작 구조가 모든 ICT 논문의 절대 표준이다.

### 최종 제출 전에 필요한 확인

- `[학과명 입력]`, `[이메일 입력]`, 영문 학과명 교체
- 동일 녹음으로 기본 STT와 PhraseSet 적용 STT를 실제 실행
- `21/30`, `27/30`, `0회`, `1회`를 실제 측정값으로 교체
- 가능하면 전체 CER, 미발화 용어 오검출, 자막 지연의 중앙값과 P95 추가
- 설명 카드의 이해 보조 효과를 주장하려면 열람률과 간단한 이해도 문항을 별도 측정
- 실제 논문·발표·데모에서 기능과 수치가 서로 일치하는지 최종 대조

## 7. 한계와 최신성

- 대회별 분량 규정은 다르므로 ABC 대회의 제공 양식과 담당자 안내가 최우선이다.
- 공개된 수상작은 아이디어·프로토타입·발표 가능성을 함께 보여주지만, 모든 논문이 엄밀한 통계 평가를 갖춘 것은 아니다.
- contextual biasing의 개념적 근거는 강하지만, 이 프로젝트의 한국어·Google STT·가정 환경에서의 실제 개선 폭은 아직 확인되지 않았다.
- 자막 UI와 학습 효과 연구는 참가자, 언어, 교육 환경이 달라 현재 프로젝트에 직접 일반화하지 않았다.
