# Lecture Context AI Presentation Design System

> ID: `lecture-context-meta-editorial`  
> Version: `0.1`  
> Status: adopted for future PPT work  
> Updated: 2026-08-09  
> Format: 16:9 PowerPoint / Google Slides

이 문서는 Lecture Context AI의 발표 자료를 Codex로 만들 때 사용하는 시각·편집 규칙이다. Meta의 제품 중심 편집 문법에서 영감을 받았지만, Meta의 공식 디자인 시스템이나 브랜드 자산을 복제하지 않는다.

PPT를 만들기 전에 다음 파일을 순서대로 읽는다.

4. 발표 시점의 실험 결과 문서 — 숫자·그래프에 사용할 검증된 데이터

## 2. 커뮤니케이션 목표

기본 발표 업무는 다음과 같다.

> 발표가 끝났을 때 청중은 Lecture Context AI가 단순한 자막 생성기가 아니라, 강연 PDF에서 검증한 용어집을 음성인식과 청중용 설명에 함께 사용하는 강연 이해 지원 시스템임을 이해해야 한다.

이 문장은 실제 발표 목적과 청중에 맞춰 수정할 수 있지만, 슬라이드 디자인은 항상 목적보다 앞서지 않는다.

## 3. 시각적 North Star

### 핵심 인상

- 밝고 정확한 제품 편집물
- 기술적이지만 차갑거나 과장되지 않음
- 실제 제품 화면이 시각적 주인공
- 코발트 하나로 시선을 통제
- 충분한 여백과 굵은 한국어 제목
- 데이터와 한계를 정직하게 표현

### 다섯 가지 원칙

1. **한 장, 한 주장** — 제목만 읽어도 발표의 논리가 이어져야 한다.
2. **제품 화면 우선** — 장식용 일러스트보다 실제 UI, 실험 결과, 문서 근거를 사용한다.
3. **강조색은 희소하게** — 코발트는 한 장에서 한 가지 메시지만 강조한다.
4. **곡률은 이미지에 집중** — 모든 내용을 카드로 만들지 않는다.
5. **의미가 수치보다 먼저** — 그래프와 숫자 옆에 반드시 해석을 둔다.

## 4. 디자인 토큰

### 4.1 색상

| Token | Hex | 역할 | 사용 규칙 |
|---|---|---|---|
| `canvas` | `#FFFFFF` | 기본 슬라이드 배경 | 전체 슬라이드의 약 60~75% |
| `canvas-soft` | `#F1F4F7` | 결과·비교 슬라이드 배경 | 연속 두 장 이상 사용하지 않음 |
| `board-gray` | `#EDF1F4` | 샘플 보드·보조 영역 | 실제 슬라이드에서는 제한적으로 사용 |
| `ink-deep` | `#0A1317` | 제목, 다크 슬라이드 배경 | 가장 강한 중립색 |
| `ink` | `#1C1E21` | 본문·표 핵심 텍스트 | 흰 배경 기본 본문색 |
| `slate` | `#5D6C7B` | 설명, 보조 텍스트 | 흰 배경에서 최소 16pt |

| `hairline-soft` | `#DEE3E9` | 매우 약한 구분선 | 카드 테두리처럼 반복하지 않음 |
| `cobalt` | `#0064E0` | 유일한 기본 강조색 | 핵심 단어, 메트릭, 진행선 중 하나 |
| `cobalt-soft` | `#0091FF` | 다크 배경의 보조 강조 | 작은 eyebrow 또는 선에 사용 |
| `dark-muted` | `#9AA8B5` | 다크 배경의 설명 텍스트 | `ink-deep` 위 본문 |

#### 대비 기준

- `ink-deep` / `canvas`: 18.78:1
- `slate` / `canvas`: 5.39:1
- `cobalt` / `canvas`: 5.39:1
- `canvas` / `cobalt`: 5.39:1
- `dark-muted` / `ink-deep`: 7.73:1

#### 제품 고유 색상

현재 제품 UI의 시안·청록 계열 색상은 **스크린샷 내부의 콘텐츠 색상**으로 취급한다. PPT의 두 번째 강조색으로 확장하지 않는다. 스크린샷 밖의 제목, 선, 차트 강조에는 `cobalt`를 사용한다.

### 4.2 타이포그래피

#### 글꼴

1. 선호: `Pretendard`
2. 오픈 대체: `Noto Sans KR`
3. PowerPoint 호환 대체: `맑은 고딕`
4. macOS 미리보기 대체: `Apple SD Gothic Neo`
5. 영문·숫자 대체: `Arial` 또는 `Aptos`

Meta 전용 서체인 Optimistic VF를 요구하거나 번들링하지 않는다. Pretendard를 사용한 PPT를 외부에 전달할 때는 글꼴 포함 여부를 확인하거나 PDF를 함께 제공한다.

#### 크기 체계

| Role | 권장 크기 | 굵기 | 행간 | 용도 |
|---|---:|---:|---:|---|
| `deck-title` | 56~68pt | 700 | 1.04~1.10 | 표지 제목 |
| `slide-title` | 36~44pt | 700 | 1.10~1.18 | 슬라이드 주장 |
| `section-title` | 44~56pt | 700 | 1.08~1.14 | 섹션 전환 |
| `metric-xl` | 76~112pt | 600 | 0.95~1.00 | 핵심 숫자 하나 |
| `subhead` | 24~28pt | 600 | 1.20~1.30 | 짧은 보조 주장 |
| `body` | 18~22pt | 400 | 1.42~1.55 | 본문 설명 |
| `label` | 16~18pt | 700 | 1.20 | 축, 범례, 단계명 |
| `caption` | 14~16pt | 400~600 | 1.30 | 출처, 단위, 주석 |

#### 규칙

- 제목은 가능한 한 한 줄, 최대 두 줄로 제한한다.
- 한 줄 제목이 의도치 않게 두 줄로 감기면 글자를 줄이기 전에 문장을 다시 쓴다.
- 본문이 많으면 글꼴을 줄이지 말고 내용을 나눈다.
- 프로젝터 환경을 고려해 300 이하의 얇은 굵기는 사용하지 않는다.
- 제목 자간은 `-1%`에서 `-3%`, 본문 자간은 기본값을 사용한다.
- 문장형 제목에 마침표는 선택적으로 쓰되, 모든 제목에 기계적으로 반복하지 않는다.

### 4.3 간격

기본 단위는 8pt다.

| Token | Value | 용도 |
|---|---:|---|
| `space-1` | 8pt | 아이콘과 라벨, 작은 내부 간격 |
| `space-2` | 16pt | 본문 줄·작은 요소 간격 |
| `space-3` | 24pt | 제목과 부제, 열 내부 간격 |
| `space-4` | 32pt | 주요 콘텐츠 블록 간격 |
| `space-5` | 48pt | 슬라이드 기본 여백, 큰 블록 간격 |
| `space-6` | 64pt | 섹션·히어로 여백 |
| `space-7` | 96pt | 의도적인 큰 여백 |

### 4.4 그리드

- 비율: 16:9
- 기준 크기: 13.333 × 7.5 inch
- 좌우 안전 여백: 최소 0.65 inch
- 상하 안전 여백: 최소 0.50 inch
- 기본 그리드: 12 columns
- column gutter: 16~24pt
- 기본 텍스트/이미지 분할: 5/7 또는 6/6
- 표지에서는 텍스트 40~45%, 제품 화면 55~60%
- 모든 슬라이드의 좌우 여백은 특별한 풀블리드 장면을 제외하고 동일하게 유지한다.

### 4.5 형태와 깊이

| 요소 | Radius | Border | Shadow |
|---|---:|---|---|
| 제품 스크린샷 프레임 | 28~32pt | 선택적으로 1pt `hairline-soft` | 없음 또는 매우 약하게 |
| 다크 결론 스트립 | 24~28pt | 없음 | 없음 |
| 일반 데이터 영역 | 0~8pt | 필요할 때만 1pt | 없음 |
| 작은 아이콘 배경 | 원형 | 없음 | 없음 |

곡률은 한 슬라이드에서 최대 두 종류만 사용한다. 둥근 사각형을 텍스트 컨테이너로 반복하지 않는다.

## 5. 핵심 컴포넌트

### `eyebrow`

- 16~18pt, 700
- 영문 대문자 또는 `01 / PROBLEM` 형식
- `cobalt` 또는 `cobalt-soft`
- 제목 위 24~40pt 위치
- 장식이 아니라 슬라이드 문맥을 표시할 때만 사용

### `claim-title`

- 36~44pt, 700
- 슬라이드의 핵심 결론을 문장으로 표현
- “문제점”, “시스템 구조” 같은 주제형 제목보다 “정답 후보는 이미 PDF 안에 있다” 같은 주장형 제목을 우선

### `product-frame`

- 실제 제품 스크린샷 1개
- 16:9, 4:3 또는 의도된 세로 crop
- 28~32pt radius
- 이미지의 중요한 UI가 잘리지 않도록 전체 슬라이드 크기에서 crop 확인
- 같은 스크린샷을 다른 슬라이드에서 재사용하지 않음

### `metric-block`

- 숫자 1개, 단위 1개, 의미 문장 1개
- 숫자는 `cobalt`, 단위와 정의는 `ink`
- 숫자 자체보다 “그래서 무엇이 달라지는가”를 가까이 배치

### `process-line`

- 3~5단계
- 얇은 수평선과 번호 원형 사용
- 단계마다 제목 한 줄, 설명 한 줄
- 각 단계를 카드로 감싸지 않음

### `dark-conclusion-strip`

- `ink-deep` 배경, 흰 텍스트
- 슬라이드 하단에 결론 한 문장
- 버튼이나 입력창처럼 보이지 않게 한다.
- 모든 슬라이드가 아니라 결과·결론 장면에서만 사용

### `source-note`

- 14~16pt
- 캔버스 하단 또는 발표자 노트의 `[Sources]` 블록
- 외부 이미지와 비자명한 외부 주장에 필수

## 6. 슬라이드 패턴

### 6.1 Cover

- 흰 캔버스
- 왼쪽: 제목, 한 문장 가치 제안, 행사명
- 오른쪽: 제품 화면 하나
- 제목 외 정보는 최소화
- 로고는 프로젝트 로고만 사용하고 Meta 로고는 사용하지 않음

### 6.2 Problem Scene

- `ink-deep` 전체 배경
- 왼쪽: 문제를 말하는 2~3줄 제목
- 오른쪽: 실제 자막/오류/사용 장면
- 본문은 두 문장 이하
- 문제를 과장하는 스톡 사진은 사용하지 않음

### 6.3 Core Insight

- 흰 캔버스
- 큰 문장 하나
- PDF 용어가 STT와 설명으로 나뉘는 최소한의 시각 관계
- 장식용 카드나 아이콘 행렬 금지

### 6.4 User Journey

- 4단계 `process-line`
- 업로드 → 분석 → 강연 → 결과
- 단계 설명은 한 줄
- 현재 단계만 `cobalt`, 나머지는 중립색

### 6.5 Validation / Before–After

- 6/6 split
- 왼쪽: 검증 전 또는 일반 STT
- 오른쪽: 검증 후 또는 PhraseSet 적용
- 바뀐 전문용어만 `cobalt`로 강조
- 성공 사례만 보여주지 말고 대표 실패 사례도 필요 시 함께 제시

### 6.6 Dual-use Architecture

- 하나의 용어집이 두 경로로 갈라지는 구조
- 중앙: 검증된 용어집
- 위 또는 오른쪽: Google STT PhraseSet
- 아래 또는 오른쪽: 청중용 쉬운 설명
- 노드는 최대 5개
- 화살표와 연결선을 먼저 만들고, 노드를 그 위에 배치

### 6.7 Technical Flow

- PDF 경로와 실시간 음성 경로를 두 개의 lane으로 분리
- PDF 경로: `cobalt`
- 음성 경로: `ink-deep` 또는 `slate`
- 실시간 합류 지점만 강조
- 라이브러리·프레임워크 로고를 나열하지 않음

### 6.8 Data / Experiment Result

- 메트릭 하나 또는 차트 하나
- 제목에서 결과의 의미를 먼저 말함
- 차트 옆에 한 문장 해석
- 표본 수, 조건, 단위, 측정 여부를 명시
- 미측정 결과는 숫자 대신 `평가 예정`, `현재 검증 범위` 등으로 표시

### 6.9 Limitation

- 결과와 한계를 같은 무게로 보여준다.
- 다크 경고 카드나 빨간색 남발 금지
- `현재 확인`, `미확인`, `후속 검증` 세 범주 정도로 단순화

### 6.10 Closing

- 표지에서 제기한 문제를 해결하는 한 문장
- 제품 화면 또는 최종 가치 제안 하나
- 일반적인 “Thank you”만 있는 슬라이드로 끝내지 않음

## 8. 차트와 표

### A/B/C 실험 색상

| 조건 | 색상 | 의미 |
|---|---|---|
| A · PhraseSet 없음 | `#B8C1CA` | baseline |
| B · canonical PhraseSet | `#718494` | 중간 조건 |
| C · spoken alias PhraseSet | `#0064E0` | 핵심 제안 조건 |

이 색 매핑은 모든 차트와 표에서 유지한다. C가 항상 가장 좋은 결과라는 의미는 아니며, 단지 프로젝트의 핵심 제안 조건임을 나타낸다.

### 차트 규칙

- 3D, 광택, 과한 그라디언트 금지
- 범례보다 직접 라벨 우선
- 한 그래프에 최대 3개 주요 시리즈
- 격자선은 최소화하고 `hairline` 사용
- y축을 임의로 잘라 효과를 과장하지 않음
- 정확도, 연결률, 등장률을 서로 바꾸어 쓰지 않음
- 평균만 제시할 때는 표본 수와 변동성을 함께 검토
- 숫자가 아직 없으면 예시 데이터로 그래프를 만들지 않음

### 표 규칙

- 기본 배경 흰색
- 헤더는 `ink-deep` 또는 매우 옅은 회색
- 핵심 행 하나만 `cobalt` 또는 진한 중립색으로 강조
- 세로선은 가급적 제거
- 셀 안 본문은 16pt 이상
- 표 전체보다 결론 한 문장을 가까이 배치

## 9. 이미지와 스크린샷

- 실제 제품 화면을 우선 사용한다.
- 한 슬라이드에 주 이미지 하나를 원칙으로 한다.
- 같은 이미지를 배경이 아닌 이상 두 번 사용하지 않는다.
- 화면 전체를 작게 넣기보다 메시지에 필요한 영역을 크게 crop한다.
- 세로형 제품 프레임은 표지나 문제 장면에서만 사용한다.
- 이미지 위 텍스트는 충분한 명도 차가 확보될 때만 사용한다.
- 외부 스톡 사진은 발표 논리를 실제로 강화할 때만 사용한다.
- 스톡 사진이나 생성 이미지를 실제 사용자·실험 참가자의 기록처럼 표현하지 않는다.
- 외부 에셋은 발표자 노트 `[Sources]`에 직접 URL을 기록한다.

## 10. 아이콘과 다이어그램

- 아이콘은 장식이 아니라 의미 구분에만 사용한다.
- 동일한 outline 또는 filled 스타일 중 하나만 선택한다.
- 아이콘 크기: 24~32pt
- 복잡한 구조를 아이콘 그리드로 대체하지 않는다.
- 단순 흐름은 PowerPoint native shape 사용
- 복잡한 네트워크는 Graphviz 사용
- 미적·과학적 인포그래픽은 별도 이미지로 제작
- 다이어그램 라벨은 가능한 한 14단어 이하
- 선이 노드·라벨을 관통하지 않도록 연결선을 먼저 생성한다.

## 11. 모션

- 모션이 없어도 이해되는 슬라이드를 먼저 만든다.
- 등장 애니메이션은 `Fade` 또는 짧은 `Wipe` 정도로 제한한다.
- 한 슬라이드에서 2종 이상의 전환을 섞지 않는다.
- 과정 슬라이드는 단계별 등장만 허용한다.
- 장식 목적의 bounce, spin, zoom 반복 금지
- 데모 화면은 실제 인터랙션으로 보여주고 PPT 애니메이션으로 흉내 내지 않는다.

## 12. 금지 패턴

- 모든 내용을 둥근 카드로 감싸기
- pill 버튼, 탭, 배지, 내비게이션처럼 보이는 장식
- 한 장에 제품 스크린샷 여러 개를 작게 나열하기
- 코발트와 제품 청록색을 동시에 PPT 강조색으로 사용하기
- Meta 로고, infinity mark, Optimistic VF를 가져와 공식 제휴처럼 보이게 만들기
- 제목을 중앙 정렬하고 본문·아이콘을 사방에 흩뿌리기
- 과도한 그림자, 유리 효과, 네온 테두리
- 의미 없는 기술 스택 로고 벽
- 한 장에 주장 두 개 이상 넣기
- 미측정 성능을 숫자나 그래프로 표현하기
- `감사합니다`만 있는 마지막 장

## 13. Codex 제작 체크리스트

### 시작 전

- [ ] 청중과 발표 시간을 확인했다.
- [ ] 발표가 끝났을 때 청중이 이해해야 할 내용을 한 문장으로 썼다.
- [ ] 실제로 검증된 주장과 아직 평가 전인 주장을 구분했다.
- [ ] 사용할 제품 스크린샷과 데이터 출처를 정리했다.
- [ ] 슬라이드별 핵심 주장만 먼저 작성했다.

### 제작 중

- [ ] 한 슬라이드에 주장 하나만 있다.
- [ ] 제목은 주제명이 아니라 takeaway 문장이다.
- [ ] 표지 제목은 50pt 이상, 본문은 16pt 이상이다.
- [ ] 텍스트가 많으면 축소하지 않고 다음 장으로 분리했다.
- [ ] 카드형 UI를 반복하지 않았다.
- [ ] 코발트 강조가 한 장에서 한 가지 의미만 갖는다.
- [ ] 제품 화면 crop에서 중요한 정보가 잘리지 않았다.
- [ ] 차트의 축, 단위, 조건, 표본 수가 정확하다.
- [ ] 외부 자료의 출처를 발표자 노트에 기록했다.

### 출력 전

- [ ] 모든 슬라이드를 렌더링했다.
- [ ] 각 슬라이드를 전체 크기로 개별 확인했다.
- [ ] 의도하지 않은 겹침, 잘림, 줄바꿈이 없다.
- [ ] 슬라이드 제목이 한 줄 의도에서 두 줄로 감기지 않았다.
- [ ] 인접 슬라이드의 실루엣이 지나치게 반복되지 않는다.
- [ ] 같은 이미지를 불필요하게 재사용하지 않았다.
- [ ] 색 대비와 프로젝터 가독성을 확인했다.
- [ ] PPT와 함께 PDF 또는 렌더 이미지도 확인했다.
